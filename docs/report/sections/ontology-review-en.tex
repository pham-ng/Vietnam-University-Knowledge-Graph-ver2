\subsection{Ontology overview}
The ontology is the conceptual backbone of the graph. It is organized around educational
organizations, people, academic programs, administrative units, ownership, governance, and
source-qualified observations. Figure~\ref{fig:ontology-er-relation-map} is the main readable
overview: every local class appears once, while color and edge style distinguish conceptual
modules, property relations, and subclass axioms.

\caption[Overview of the VN-Edu ontology]{Overview of the VN-Edu ontology. Each local class is

The map is intentionally similar to an ER/UML or GraphRAG schema so that a project reader can
see the domain at a glance. It is not a relational schema: OWL uses an open-world assumption,
property assertions can entail types through domain and range, and omitted triples mean unknown
rather than false. The formal model is the Turtle ontology; the diagram is a communication view.

\subsection{TBox structure and property semantics}
The TBox contains \metricClasses{} local classes, \metricObjectProperties{} object properties,
and \metricDataProperties{} datatype properties. Figure~\ref{fig:tbox-architecture} combines
the class hierarchy with representative property signatures and one property-chain inference.
It is the formal design view: the upper part shows predicates and their domain/range links,
while the lower part shows the class hierarchy. Disconnected root concepts are retained because
adding a superclass merely to make a picture connected would change the ontology semantics.

\begin{figure}[htbp]\centering
\IfFileExists{docs/report/figures/tbox-architecture.png}{%
  \includegraphics[width=\textwidth,height=0.86\textheight,keepaspectratio]{docs/report/figures/tbox-architecture.png}%
}{%
  \includegraphics[width=\textwidth,height=0.86\textheight,keepaspectratio]{figures/tbox-architecture.png}%
}
\caption[TBox class hierarchy and property signatures]{TBox class hierarchy and representative
property signatures generated from the committed ontology. Blue edges are subclass axioms, purple
diamonds are properties with domain/range links, and the highlighted chain shows the selected
\texttt{offersProgram}/\texttt{ofMajor} entailment.}
\label{fig:tbox-architecture}
\end{figure}

The main design decisions are:
\begin{itemize}
\item governance, state oversight, membership, branch structure, and ownership are distinct
relations rather than one generic parent relation;
\item people, leaders, alumni, and education participants are separated so that recorded
education does not entail graduation or employment;
\item former provinces, current provinces, containment, and merger relations are directed and
time-qualified in interpretation; and
\item qualified observations preserve source context and optional dates without asserting that
an undated leadership or measurement is current.
\end{itemize}

\subsection{Reasoning and conformance}
The implementation uses the \texttt{owlrl} rule engine for OWL/RDF rule materialization and
an OWL API \texttt{OWL2RLProfile} gate for the committed ontology. The gate reports zero profile
violations. SHACL reports zero violations, 34 warnings, and one informational result under the
current policy. These results establish local conformance to the implemented profile and shapes;
they do not establish completeness or factual accuracy of the source records.

Representative entailments include inverse relations, organization-to-province containment,
and the chain
\[
\texttt{offersProgram} \circ \texttt{ofMajor} \sqsubseteq \texttt{trainsMajor}.
\]
The model deliberately avoids using domain/range as if they were SQL foreign-key rejection
rules. Operational requirements such as required fields, valid year ranges, and observation
interval ordering are enforced by raw checks and SHACL.
